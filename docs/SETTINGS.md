# Settings

One Settings window for R5. Existing preference programs stay separate and keep their own files.

## Host

`Settings` is a single-launch preference (`application/x-vnd.R5OS-Settings`). The window is a sidebar, a search field, and one content deck (`BCardLayout`). Changing page does not create a new window. The regular image and the minimum image both install this program, the fonts and look modules, and `libr5icons.so`. Settings links that shared library.

This frame is fixed (`AGENTS.md`). The picture it follows is `docs/design/settings-mockup/`. The list shows Home, then the categories. Only the category of the open page is unfolded. Search filters the list. The list starts under the tab and runs down to Search. The heading is one card beside the list, and that page's icon sits at the right of the title. The page content is under the heading. When that content is taller than the area, the page scrolls and the scrollbar is visible. Search stays under the list. The bottom row is the lock, Revert, and Defaults. There is no Back button and no Home button. Home is the first list item. The lock calls `r5_button_set_lock()` so it matches the height of Revert and Defaults. The lock does not get the preferences wrench. The lock is closed (`R5_ICON_LOCKED`, Haiku `Action_Logout`) until an administrator password opens it (`R5_ICON_UNLOCKED`, Haiku `Action_Login`). One open lock covers every page in this window that requires an administrator, for the same few minutes as the other locked preferences. An administrator account starts open. While a page is locked its controls are gray and nothing is written. The list on that page still scrolls. Search and the sidebar stay usable. The window opens at 1030 by 610. The list and Search are 200 wide. A home card is at least 280 wide. The shortest size is 910 by 560. The list scrollbar is there only when the items are taller than the list. A category card lights up under the pointer and looks pressed while the mouse button is held down.

A box title written as ordinary text is bold. That is the screen size (or Display) and Workspaces, Applications, Menu, Window, Preview, Device, and R5 Operating System. A checkbox that sits on the box border is bold when it is Enable notifications or Enable virtual memory. A menu on the box border stays in the plain font.

A change is applied as soon as it is made. Revert restores the values from when the page was opened and applies them. Defaults restores a page's factory setup and applies it. Desktop and Deskbar, Notifications and Power have a factory setup. Defaults stays disabled on the others.

A new page adds its icon signature in `module_icon()` in `SettingsWindow.cpp`. Home uses the R5 wave pebble (the same HVIF as About R5). The Settings application icon is that pebble with the preferences wrench. Information uses the About icon. Every one of those page icons, and the icons on the home cards, has the Haiku preferences wrench drawn on top. The wrench is the unmodified Haiku file `overlay-prefs.hvif`. It belongs to this Settings application and its modules. About R5 is not a settings module and does not get the wrench.

Display is a page under System. The subtitle is "Screens, resolution, and workspaces". The separate Screen program stays installed. The page is locked until an administrator opens the lock. The arrangement is `BScreenArrangement` (`docs/LIBR5.md`), which draws each screen with `r5_screen_draw()`. With one screen the tile is centered, it cannot be dragged, and Identify, the screens menu, Scale, Rotation, Main screen, and Mirror or Extend stay off the page. The name comes from `BScreen::GetMonitorInfo()` (vendor and name). When that is empty the name is Screen. The box title is "Screen – " plus that name. The two boxes use the same light fill as the Information tiles: the panel background mixed toward the document background by 100, from the one call `r5_settings_tile_fill()`. The fill starts at the top border line. The box title sits on that line with window grey above it and the fill below, as in the mockup. Their border is `tint_color()` of the panel with `B_DARKEN_2_TINT` (`#c4c4c4`). The arrangement picture uses the list background mixed toward `B_CONTROL_HIGHLIGHT_COLOR` by 18, and that mix at 48 for the border (`#f3f6fb` and `#dbe3ef`). Hint text (`#64748b`) is the document background mixed toward the document text by 140. The workspace sentence (`#475569`) is that mix at 160. The workspace grid is one dark plate (`#3b3f46`: the panel mixed toward the document text by 200) with corners of u·3, and the cells sit on it u·3 apart, so the gaps are the frame colour. The other workspaces are the desktop colour (`BScreen::DesktopColor()`) tinted `B_LIGHTEN_2_TINT`, so they follow the desktop, also right after a change on Wallpaper or a colour dropped on the desktop. The selected screen and the current workspace use `B_STATUS_BAR_COLOR`. Columns and Rows share one label width, so their fields line up. Colors is shown only when the screen offers more than one depth. Resolution marks the largest mode "(recommended)". Workspaces change the column and row count immediately. A click on a cell calls `activate_workspace()`. Resolution, colors, and refresh wait for Apply. Apply asks to keep the picture. After 12 seconds without a choice the previous picture returns. Revert restores the mode and the workspace layout from when the page was opened. Notifications and Desktop and Deskbar still call `r5_screen_draw()` themselves.

Information is a page under System. It shows one device card, six tiles, one Copy details button, and a footer. The device card has the computer's name, a Rename… link, and the R5 version. The model line is shown only when a program can read it. It is left out: the kernel logs the vendor and product in `smbios_scan`, and `generic/smbios` only offers `match_vendor_product()` to other kernel code. A program has no public way to read those two strings. Showing the line needs a small additive call that returns them. That call is not part of this page, and the kernel is not changed. Rename… writes the name with `sethostname()`, the call Network already uses. That call stores the name in the existing network hostname file (`B_SYSTEM_SETTINGS_DIRECTORY` / `network/hostname`), which is what `gethostname()` reads, so the new name shows up without a restart. The name may use letters, digits, and `-`, at most 63 characters, and it does not start or end with `-`. The link stays grey until the lock is open. Copy details copies every line on the page. The tiles are Processor, Memory, Storage, Graphics, Display, and Running for. Storage is the boot volume. There is no device id. The build date is the Europe/Amsterdam time of the image jam. Graphics says the desktop is drawn by the processor, because the app server does not use the GPU yet. Memory in use and Running for refresh every 2 seconds while the page is visible. The quiet text (`#64748b` in the mockup) is a mix of the document background and the document text, amount 140. The tile detail (`#475569`) is the same mix at amount 160. The model line, when it exists, would use that mix at amount 190 (`#334155`). Tile fill (`#e4e4e4`) is a mix of the panel background and the document background, amount 100: a darkened panel tint was much darker than the mockup on the Haiku panel grey. Borders are `tint_color()` of the panel background with `B_DARKEN_2_TINT` (`#c4c4c4`). The usage track (`#c9cfd6`) is the tile fill mixed with the document text, amount 40, so it stays visible in dark mode. The Rename… and What's new links are underlined, as in the mockup. The usage fill is `B_STATUS_BAR_COLOR`, the blue of a selected row in the list. The window grey stays `B_PANEL_BACKGROUND_COLOR`.

The sidebar and the home cards are filled from the module list. Pages under a category are alphabetical by name. Information stays first under System. A category card and the subtitle of an open page use that page's description. Leave that order, and these five descriptions, as they are until the user explicitly asks to change them. Another Settings task does not include reordering the list or rewriting these lines. Information is "View system details". Virtual memory is "Extra memory stored on disk". Wallpaper is "Set the background of your desktop". Desktop and Deskbar is "Adjust desktop and Deskbar settings". Notifications is "Manage alerts and notifications". Category names for `personalization`, `system`, `devices`, `network`, and `accounts` live in one table in `SettingsWindow.cpp`. Personalization's summary is fonts, look and feel, wallpaper, and the Deskbar. System's summary is display, sound, notifications, virtual memory, and this computer. Devices' summary is keyboard, mouse, touchpad, printers, and Bluetooth. Network's summary is wired and Wi-Fi connections, and network shares. Accounts' summary is the people who use this computer, and how they sign in. A module with another category id is still shown. A category page uses the same cards as Home and does not repeat the category summary under the title. The sixth place on Home is Recently changed: the last three pages that were changed, newest first. Before any change it says "Nothing changed yet". Those names are stored in `~/config/settings/r5-settings/settings-window`. The lock, Revert, and Defaults sit on the bottom row.

Manrope Regular and Bold are the default plain and bold fonts when no font settings are saved. The fixed font stays Noto Sans Mono. The files are installed in `data/fonts/ttfonts`. Settings still selects Manrope for its own window, and falls back to the system font if that family is missing. The page title is the bold face, eight points above the bold system size.

Wallpaper is the Backgrounds window, rewritten as this page. The picture, placement, icon-label outline, and desktop color sit on the left. The preview sits on the right. A change writes `be:bgndimginfo` on the Desktop folder, or on a folder, then asks Tracker to restore the picture. The workspace menu on the page chooses the current workspace, every workspace, or a folder. The desktop color is `BScreen::SetDesktopColor`. A colour dropped on the desktop in Tracker reaches Settings too: Tracker sends it to Settings as it does to Backgrounds, and every page that was opened gets `kMsgDesktopColorChanged`. Wallpaper takes the colour without writing it again, so a later change on the page keeps it; Display redraws the workspaces. The separate Backgrounds program stays on the disk and is not a page in this window.

Desktop and Deskbar is a page under Personalization. Each change messages the running Deskbar (`application/x-vnd.Be-TSKB`) immediately, including the icon-size slider and the application checkboxes. It does not write `~/config/settings/deskbar/settings` itself. Deskbar writes that file when it quits. Auto-hide is the exception Deskbar already had: that one is written immediately. The clock stays out of this page. The separate Deskbar preferences program stays installed. Since 25 Nov 2026 "Deskbar preferences…" in the Deskbar menu, and that program, open this page (`r5_settings_open_page("deskbar")` for `kConfigShow`); Deskbar's own preferences window is no longer opened. The Deskbar menu also has a Settings item with the R5 wave pebble, under Mount, that opens Settings on Home. Where the bar sits is a picture of the screen: the top and bottom edges, the four corners, and a taller bar on the left or right top for the application list. Show applications follows that picture for the top corners. Applications and Menu sit next to each other, and Window is underneath both, so the page fits in the window.

The page reads that settings file for the application list, the icon size, and the recent counts, because Deskbar has no public getter for them. The place and the three window flags come from `BDeskbar` when Deskbar is running. Sort, Tracker first, the expanders, and hide names are toggles: a change sends one message only when the value differs from what this page last sent, starting from the file read at load. Icon size (`be:value` times 8) and the recent counts are absolute. Location uses `BDeskbar::SetLocation`. Top and bottom are always expanded. Left bottom and right bottom are not. Show applications is only offered for left top and right top. Always on top is sent before auto-raise, and auto-raise is not sent while always on top is on. A recent count of 0 is stored by Deskbar as off. Defaults applies Deskbar's own defaults immediately. Revert applies the values from when the page was opened. Edit in Tracker opens `B_USER_DESKBAR_DIRECTORY` with `B_REFS_RECEIVED`. The count fields are `BSpinner`. The class lives in `libbe`. The header is private, so the Settings Jamfile has `UsePrivateHeaders interface`, the same way Deskbar's own window includes it. "Expand new applications" is indented by 20 pixels under "Show application expander". That indent is a real width. `B_USE_DEFAULT_SPACING` is a negative layout constant and must not be passed to `CreateHorizontalStrut()`.

Notifications is a page under System. The card on that category uses the page description. The icon is the Notifications program (`application/x-vnd.Haiku-Notifications`), with the same wrench as the other Settings icons. A change writes `~/config/settings/system/notifications` immediately. That is the file the notification server reads. The page does not keep a second copy under `r5-settings`. The directory `settings/system` is created for the signed-in user by `r5-desktop` before the desktop starts. The image ships `config/settings` as root, mode 0755, so a new directory there was permission denied and the example was never sent. Enable notifications and Applications sit next to each other and share the same height, so the page fits in the window. Where the message appears is a screen picture. The four corners place it there. The bar on that screen follows the running Deskbar and means Follow Deskbar. Width, timeout, and position send one sample notification after a successful write. Enabling notifications, and muting an application, do not. Defaults restores enable, a 10 second timeout, a width of 300, and the lower right. It leaves the application list and a stored icon size alone. Revert restores the values from when the page was opened, including the list. The separate Notifications program stays installed.

Power is a page under System, between Notifications and Virtual memory by name (docs/POWER.md, section 2; the picture is `docs/design/power-mockup/`). The title is Power, and the subtitle and the home card read "Battery, performance and sleep". The icon is PowerStatus (`application/x-vnd.Haiku-PowerStatus`, Haiku's `App_PowerStatus`) with the same wrench. Two columns: Battery with Sleep under it on the left (the wider one), Performance with Wake under it on the right. Battery shows the `R5_LEVEL_BATTERY` glyph, the charge, "On battery · about N h N min left" (or Charging, or Plugged in), and the battery health when the firmware reports the design capacity; it is hidden without a battery. Sleep is a grid with "On battery" and "Plugged in" (one column without a battery): "Turn off the display after" (Never, 1, 2, 5, 10, 15, 30 minutes) and "Put the computer to sleep after" (gray), then "When the lid is closed" (hidden without a lid), "When the power button is pressed", "Keep working with an external display", and the note that sleep is not available yet. Until sleep works, the choice Sleep is gray in both menus and the Wake box is gray. Performance has the profile (Power saver, Balanced, Performance) per power source, one line that explains the profile in use, and the brightness slider, which is `BScreen::SetBrightness()` and is hidden where `GetBrightness()` fails. On a processor without speed control the profile menus are gray with "This processor does not let R5 change its speed." The settings are machine-wide. Like Bluetooth, the page does not require an administrator as a whole: Battery and brightness are for everyone, and on `kMsgRefreshPage` the page grays the profile, Sleep and Wake while the lock is closed. A change goes to the power service as an admin request (`BPowerRoster::SetSettings()`, `libr5power.so`); the service checks the sender and writes `B_SYSTEM_SETTINGS_DIRECTORY/power` itself, and the page never writes it. Revert restores the settings and the brightness from when the page was opened. Defaults restores the factory setup of POWER.md section 7 (with "Turn off the display" for the lid and "Ask" for the button while sleep does not work) and leaves the brightness alone. Without the power service (Safe mode) the page says "Power settings are off in Safe mode." and grays every group but Battery. Dimming on battery comes with POWER.md step 3. The separate PowerStatus program stays installed and reads the battery through the same library.

Virtual memory is a page under System. It requires the lock. The icon is the VirtualMemory program (`application/x-vnd.Haiku-VirtualMemory`), with the same wrench. A change writes `/boot/system/settings/kernel/drivers/virtual_memory` immediately, in the same text the kernel already reads. That takes effect on the next start. Swap can be on or off, automatic or a chosen size on a chosen volume. Turning swap off asks first. Defaults is swap on, automatic, on the boot volume. Revert restores the values from when the page was opened. The separate VirtualMemory program stays installed. When the settings file cannot be read, or names a volume that is not there, a line above the box says so, and the page shows the defaults or the boot volume; the next change writes them and the line goes. The program asked the same in an alert. While the lock is closed the controls are gray and the file is not written.

Search compares the module name, description, keywords, and category label. Clearing Search shows the whole list again, including the category that was unfolded.

Leaving a page does not ask, because the change is already applied.

Page changes are immediate. There is no compositor, so the window does not animate a transition (`docs/LOOK.md`).

## Modules

The contract is `distro/settings/SettingsModule.h`, version 2. `distro/settings/ModuleAPI.md` is the developer note.

`SettingsManager` loads add-ons from the `Settings` directories under the system and user add-ons paths, including `non-packaged`. It checks `settings_api_version()` before `instantiate_settings_module()`. A wrong version is not loaded. Images stay loaded until the modules are deleted, then `unload_add_on` runs.

Every page is an add-on of its own (owner, 25 Nov 2026). The Settings program has no pages built in. The list of add-ons and what a new page needs is in `distro/settings/ModuleAPI.md`. A page reads its settings (`LoadSettings()`) when it is first opened, not when Settings starts.

Theme (`ThemeModule.cpp`, the add-on `settings_theme`, 23 Nov 2026) is a page under Personalization, after Desktop and Deskbar. Its subtitle is "Choose how windows, controls and the Deskbar look". It shows the theme cards (the built-in R5 Modern, R5 and Classic (Haiku), the saved ones, and a dashed "Save as theme…" card), Mode (Light, Dark) and the accent, and a Parts box that folds: Windows and Controls with About, Scrollbars (style, arrows, a live preview), Deskbar (style, layout, Rounded, Away from the screen edges) and Effects. "Save as theme…" and "Delete" sit above the cards. A change is applied at once through libr5ui's `set_theme()` (`docs/LIBR5.md`, "Themes"), which sets each part with the calls Look and Feel and Desktop and Deskbar use, and the page writes no settings file of its own (libr5ui keeps the theme in use in `~/config/settings/r5/theme`). Revert puts back the theme and every colour from when the page was opened; Defaults chooses R5, light. The page is not locked. The plan is `docs/design/THEMING.md`.

Fonts (`settings_fonts`) and Look and Feel (`settings_look`) were pages under Personalization. Look and Feel was merged into Theme; `settings_look` and `LookModule.cpp` were removed on 25 Nov 2026. There is no Appearance page and there are no tabs. Fonts uses the font rows from the separate Appearance program. Its subtitle is "Change the default fonts". Antialiasing is a box on that page. Look and Feel uses the decorator, control look, and arrow style from that program. Its subtitle is "Change the default decorator and colors". Colors is a box on that page. A change is applied at once, through the same calls the separate program uses. Neither page writes a settings file of its own. Revert and Defaults are the window buttons. The pages are not locked. The separate Appearance program stays installed. Both pages use that program's icon. The other four category descriptions stay as they are.

## Network

Network has three pages: Connections, Discovery and Wi-Fi. Connections and Discovery need the lock. The separate Network program stays installed.

Connections ("Wired connections, addresses, and DNS") lists the network cards with a dot and their status. The card's box has its on/off switch as the title (drawn like `BoxTitle`), the status with the link speed (`media_type_to_string()` of ifconfig) and the hardware. IPv4 and IPv6 sit side by side, equally wide, built as `InterfaceAddressView` of the Network program builds them: Configure (Automatic, Manual, Off), the address fields (`IPAddressControl`), and Apply, which is shown only for Manual. A manual address waits for Apply; the other changes are applied at once. IPv6 Automatic lists every address of the card; an address that does not fit ends in "…" with a tooltip. DNS shows the servers and the search domain; Edit… sets them by hand (`# Static DNS Only` in `resolv.conf`) or gives them back to the network. Wi-Fi in the list opens the Wi-Fi page. "Show in Deskbar" is the Network program's NetworkStatus switch. Like Display, a change is applied after `AdminChangeAllowed()` through the calls the Network program uses (`BNetworkSettings`, `BNetworkInterface`). Revert applies the setup from when the page was opened. Defaults is automatic IPv4 and IPv6, every card on, and DNS from the network.

Discovery ("Find devices and services on this network") shows the computer's name with Rename… (the same `sethostname()` and check as Information), its `.local` name, and "Let other devices find this computer", on by default, in `B_SYSTEM_SETTINGS_DIRECTORY/network/discovery` (`discoverable true|false`), which `r5-mdns` reads. Shared from this computer loads the Network program's service add-ons (`Network Settings`) and lists those with an Enable button (`ServiceView`): FTP, SSH, Telnet, beside the chosen service's text and button. Find devices lists printers, AirPlay speakers, SSH and file sharing through `r5_mdns_browse()`, with Refresh. Revert puts back the name, the setting and the services. Defaults is found by others, SSH and FTP off; the name stays.

## Bluetooth

Bluetooth ("Find Bluetooth devices nearby") is a page under Devices, first by name. It replaced the Bluetooth row in `LegacyPages.cpp`, in the same place. It is the `BluetoothView` of `libr5bt.so` in the add-on `settings_bluetooth` (`distro/settings/BluetoothModule.cpp`, `docs/LIBR5.md`, "Bluetooth Kit"), in the regular and the minimum image (since 25 Nov 2026, issue #4615); Settings itself does not link `libr5bt.so`, so it starts without this page where the add-on is missing: My devices (the paired devices, and a panel for the one chosen: status, Classic or Low Energy, address, Disconnect and Forget), the devices nearby with Pair and Scan down to the last line, and that last line without a box: "Bluetooth on" with the radio in use ("No Bluetooth radio was found." without one). `bluetooth_server` is a system service from boot; when it is not running, the page asks launch_daemon to start it. The Bluetooth program (R5's, step 3b; it replaced Haiku's Bluetooth preferences) shows the same panel in a window, and the Bluetooth item in Deskbar opens it.

This page is an exception to the rule that a page requiring an administrator is gray until the lock is open. Only the Bluetooth switch is system-wide, so only that switch is gray while the lock is closed, with "Only an administrator can turn Bluetooth on or off." beside it. Scan and the device list work for every signed-in person. The module keeps `RequiresAdmin()` false and catches `kMsgRefreshPage`, which the window sends when the lock opens or closes, to enable or disable the switch through `AdminChangeAllowed()` (`r5_admin_change_allowed()`). The switch writes through `bluetooth_server`, not through Login; the server checks the sender itself (an administrator, or a team with a grant) and, running as uid 0, writes its own `/boot/system/settings/bluetooth` (mode 0700). A change is applied at once. There is nothing to put back and no factory setup, so Revert and Defaults stay disabled.

## Game controllers

Game controllers ("Test your controllers and set up their buttons") is a page under Devices, between Bluetooth and Keyboard by name. It is the add-on `settings_gamecontrollers` (`distro/settings/GameControllersModule.cpp`, regular and minimum image), which links `libr5game.so` (`docs/LIBR5.md`, "Game Kit"); Settings itself does not. The icon is the Devices icon with the wrench. The picture it follows is `docs/design/gamecontrollers-mockup/`.

The page follows layout A of the mockup (`strip-A-*.png`, approved 17 Nov 2026). At the bottom, as wide as the page and always in view, a `BCardStrip` (`docs/LIBR5.md`, "Card strip") with a card per controller under `/dev/joystick`: a small picture of its model (`BGameControllerView::PictureBitmap()`), the name in bold, and the connection with the battery when the controller reports it ("Bluetooth · 80 %", "USB"). A click or the left and right arrow keys choose a card; the chosen one has the accent border. When the cards do not fit, the strip scrolls sideways. Above the strip one filled box (Display's, without a title): one row with "Layout" (Automatic, Xbox, PlayStation, Nintendo, Sega Genesis, and the gray "Your own setup", marked while a setup is saved), "Button labels" (Xbox or PlayStation) and the button "Set up buttons…" at the right; under it the live `BGameControllerView` of the chosen controller at the left, with the hint and the vendor and product ID under it, and the groups of the next paragraph at the right. Layout chooses where the buttons are and how they are read (the shape, and a fixed mapping); Button labels chooses only what is printed on the face buttons. They stay two menus because they answer two questions: a third-party pad can have the PlayStation shape with Xbox letters. The label menu is gray for the Sega shape, a controller without a mapping, and a controller without IDs; Layout and Set up buttons… are gray for a controller without IDs (the choice is stored per model). Where the picture and the groups do not fit side by side (the box is narrower than the picture at its smallest plus the groups), the groups go under the picture; the part above the strip then scrolls by itself, so the strip stays at the bottom, and the window's own page scrollbar does not appear. The "Shapes R5 draws" strip is gone (owner, 17 Nov 2026: of no use); `BGameControllerView` keeps the shapes. Until 17 Nov 2026 the controllers were a column of `BCard`s at the left and the rest a box called Test.

Without a controller (`strip-empty-*.png`) the page shows what it does, gray: an example picture (the Xbox Series shape, nothing lit, no trigger caps), the menus and Set up buttons… disabled, and Rumble, Motion and Trigger feedback with their buttons, menu and sliders disabled and their text gray. The strip holds one dashed card, "No controller" / "Plug one in with USB, or pair one in Bluetooth.", with the button "Open Bluetooth…", which opens the Bluetooth page. A controller that connects replaces it at once.

"Set up buttons…" opens a small window (modal to Settings) with the controller's name, one question at a time ("Press A, the lower face button", "Pull LT, the left trigger", "Push the left stick to the right", "Press the d-pad up", "Press Start", "Press Select"; for the Sega shape A, B, C, X, Y, Z, L, R), "Step n of m", and Skip and Cancel. It notes the first raw button, straight hat direction or axis moved more than half way from where it rested, waits until that control is let go, and goes on. At the end the setup is saved for the model (`BGameController::SetSavedMapping()`) and the picture follows it at once. Cancel saves nothing. The window is closed when the page goes, because its code is in the add-on. The page watches for controllers (`BGameController::StartWatching()`), so a card comes and goes when a controller is plugged in, paired, unplugged or turned off, and reads the chosen controller's battery every 10 seconds.

The choices are the person's own, so the page needs no administrator. A change is written at once by `BGameController::SetLabelStyle()` (the family's own labels are stored as Automatic), `SetLayout()` and `SetSavedMapping()`. A layout from the menu replaces a saved setup. Revert puts back the labels, the layout and the setup from when the page was opened, for every controller the page showed or changed. Defaults removes every label choice (`ResetLabelStyles()`), so each controller shows its own family's labels again, and removes the chosen controller's layout and setup, so it follows the database again. The Bluetooth page's "Test buttons…" opens this page (`Settings --page gamecontrollers`).

Beside the picture (under it in a narrow window) are three groups (option C, phase 1, 17 Nov 2026, after `feedback-light.png` and `feedback-dark.png` in the mockup folder), each a thin box with a bold title, shown only when the chosen controller has the feature: **Rumble** ("Light" and "Strong", one second on both motors, three small accent arcs while it runs, "One second, both motors."), **Motion** (`BGameControllerMotionView`: the Tilt level and the Pitch, Roll and Yaw bars over Turn; the page switches motion on and shows the last sample 30 times a second) and **Trigger feedback** (DualSense and Edge only: "Effect" Off, Resistance, Trigger click or Vibration "on L2 and R2", and the sliders "Starts at" and "Strength" with their percentages; a change applies at once to both triggers, and a tick on the L2 and R2 caps of the picture shows where the effect starts). Without a controller all three are shown, gray (above). Nothing of it is stored: Revert and Defaults do not touch it, and choosing another controller or leaving the page closes the controller, which stops the rumble and frees the triggers. The 8BitDo M30 shows none of the three groups. Phase 2 (17 Nov 2026): a Switch Pro Controller shows Rumble and Motion, a Joy-Con Rumble, an Xbox controller Rumble with a third button **Triggers** (one second on the two motors in the triggers, at 60 %), shown only for a controller with trigger motors (Microsoft's Xbox controllers). Trigger feedback stays DualSense only: the Xbox trigger motors rumble, they do not push back.

## Accounts

Users and Accounts ("People on this computer.") is a page under Accounts, the add-on `settings_accounts` (`distro/settings/AccountsModule.cpp`, with the windows in `AccountDialogs.cpp`; owner, 24 Nov 2026, issue #66). It replaced the Users and Accounts row in `LegacyPages.cpp`, with the same id `accounts`, so its icon in `module_icon()` is still the Users & Accounts program. The page follows the mockups in `generated/GEMINI-ACCOUNTS-SECURITY-PROMPT.md` ("The mockups"). The word is "account" everywhere, never "person" or "people".

Left, about 300 wide: the caption "ACCOUNTS" over the list. A row has the round picture, the name in bold, "@username" in small gray text with "· you" for the signed-in account and "· disabled" (and the row faded) for a disabled one, and a pill "Admin" (accent tint) or "Standard" (gray). The row is `BAppearanceKit::BUserListItem` with its own drawing. Under the list: "Add account…", "Disable account" or "Enable account", and "Delete account…". Under those buttons: the caption "GUEST AND SHARING" over a `BCard` with the switch "Allow guests to sign in to this computer" ("No password. Everything is deleted at log out."), a separator, and the "Shared folder" row (`/boot/home/Shared`, folder icon, and an "Open" button that opens it in Tracker). The guest switch is off by default, stored machine-wide by Login via `kMsgAdminGetGuestEnabled` / `kMsgAdminSetGuestEnabled` (`r5_admin_send()`), and requires an administrator. Right: a caption with the account's name over a `BCard`: the picture (64) with the name, "@username · Administrator · home /boot/home" with "Choose picture…" and "Remove picture" (gray without a picture; Login removes the stored picture and the initials come back); then Name, Email (placeholder "name@example.com"), Account type (Administrator, Standard) and Password ("Change password…"); then "Changes are saved as you make them. The last administrator cannot become a standard account." Under the card a gray `BCard` says what a standard account sees.

Every change goes to Login through its admin port (`r5_admin_send()`, as the separate program), and Login decides. A new request, `kMsgAdminListAccounts`, gives the accounts with their type and whether they are disabled (Login is uid 0 and can read that); an administrator, or a team with a grant, gets every account, anyone else only the own one. A second one, `kMsgAdminSetAccountType`, makes an account an administrator (the `admin` group) or a standard account (out of `admin` and `wheel`); it needs an administrator and refuses the first administrator (home `/boot/home`), an administrator through uid or gid 0, and the last enabled administrator. So the page does not require an administrator as a whole: on `kMsgRefreshPage` it reloads, and with the lock closed a standard account sees only its own card. Name and Email are saved on Enter or when the field loses the focus, a picture, the type and Disable at once. Delete asks first (Keep files, Delete files). Disable and Delete are gray for your own account, the first administrator and the last enabled administrator. A picture is cut to the middle square and stored at 128 by 128.

Revert puts back, for every account changed since the page was opened, its name, email, picture, type and whether it is disabled, as well as the guest sign-in switch; type, disabled and the guest switch only while the lock is open. It does not undo a password, an added or a deleted account. Defaults stays disabled: accounts have no factory setup.

"Add account" (480 wide) has the picture with a camera badge, "Add an account", Name (focused), Username (a suggestion from the first word of the name, and "home: /boot/home/users/<username>" inside the field), Account type as two choices (Standard is the default), Password and Repeat password with the eye of `BPasswordControl`, a strength bar of four parts with one line (a hint only, it never blocks) and the match line. "Add account" stays gray until the name, a free valid username and two equal passwords are there. "Change password" for yourself asks the current password, the new one with the strength hint, and the repeat; for another account an administrator gets no current field and the yellow note about saved passwords (the key store reset of step 2). The fields of both windows are drawn like `BPasswordControl`, so they match. A password copy is wiped after use and never logged; it travels only in the admin request to Login. The separate Users & Accounts program stays installed, with the same words ("Accounts", "Add account…").

## Legacy programs

`LegacyPages.cpp` is a table of programs that already exist: Sounds, Keymap, Input and Printers. Each row is an add-on of its own (`settings_sound`, `settings_keyboard`, `settings_mouse`, `settings_printers`; `LegacySound.cpp` and the others). Users & Accounts left this table on 24 Nov 2026 (section Accounts). Each row is a page with an Open button. `BRoster::Launch` starts that program. Nothing is embedded, because those programs are windows, not views we can reuse. Appearance, Screen, Backgrounds, the Deskbar preferences program, Notifications, and VirtualMemory stay installed and are not in this table.

Adding a row there is how an old preference shows up before it is rewritten. A new native page does not need a row and does not need a change to the window.

## Storage and the administrator lock

New R5 values are `BMessage` files under `~/config/settings/r5-settings/<module id>`. The id is checked so one module cannot name another's file. Haiku files such as `Appearance`, `Keyboard`, and `Network` are not moved.

`SettingsHost::AdminChangeAllowed()` calls `r5_admin_change_allowed()` from Users & Accounts. The window refuses the write when the module says `RequiresAdmin()` and that call is false. The module repeats the check in `SaveSettings()` before a privileged write. The lock button uses `r5_admin_query()`, `r5_admin_prompt_unlock()`, and `r5_admin_relock()`. The picture is `r5_button_set_lock()` in `libr5icons.so`.

## Not in this foundation

Storage, sharing, sign-in options, permissions, installed applications, and default applications have no page yet. Catalogs are not wired, so the strings are English.
