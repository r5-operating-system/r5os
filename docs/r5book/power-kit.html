libr5power.so

The Power Kit

R5's libr5power.so tells a program about the batteries, the power source, the processor's profile and sleep, and sends it a message when one of them changes. It sits next to libbe and is not part of it. Reading needs no rights; the machine's power settings are changed through the power service, which checks who asks. The code is R5's own and MIT; the battery reading is the code PowerStatus always used, moved into the library.

Who does what. The kernel sets the processor's speed: a profile, written to the processor's own registers (AMD CPPC, Intel HWP). The power service, Haiku's power_daemon, chooses the profile for the power source, turns the display off after the time the person chose, and handles the lid and the power button. A program only reads and watches. The values come from the processor and the firmware (ACPI), never from a list of models.

BPowerRoster

class
Declared in<PowerRoster.h>
BPowerRoster();
~BPowerRoster();

A roster finds the batteries under /dev/power when it is made. Make one where you need it; it is cheap.

int32 CountBatteries() const;
status_t GetBatteryInfo(int32 index, power_battery_info* info) const;

The batteries, read again on every call. power_battery_info holds state (B_POWER_BATTERY_DISCHARGING, _CHARGING, _CRITICAL, _NOT_CHARGING), percent (0 to 100), time_left in seconds until empty or full, health (the full charge in percent of the design capacity), the three capacities and in_mah. A value the firmware does not report is -1.

bool IsOnAC() const;

True when the computer is plugged in, and on a computer without a battery. From the ACPI AC adapter, or from the batteries when there is none.

power_profile Profile() const;
bool CanChangeProfile() const;

The processor's profile: B_POWER_PROFILE_SAVER (stays below its boost, leans toward energy), B_POWER_PROFILE_BALANCED or B_POWER_PROFILE_PERFORMANCE. CanChangeProfile() is false on a processor that offers R5 no speed control; the profile then does nothing.

bool CanSleep(power_sleep_state* state = NULL) const;

Whether sleep works on this computer, and the state the firmware offers: B_POWER_SLEEP_S0IX (Modern Standby), B_POWER_SLEEP_S3 (suspend to RAM) or B_POWER_SLEEP_NONE. Until R5's sleep has passed its tests it is false everywhere.

status_t GetSettings(BMessage* settings) const;
status_t SetSettings(const BMessage& settings);

The machine's power settings, the ones on the Power page. Reading needs no rights. SetSettings() is an admin request: the power service checks that the sender is an administrator, uid 0 or a program the lock was opened for, and writes the file itself. Both return B_NO_INIT when the service does not run (Safe mode). Most programs do not need these.

Watching

messages
static status_t StartWatching(BMessenger target);
static status_t StopWatching(BMessenger target);

The target gets kMsgPowerChanged whenever something changes, so a program never polls. Stop watching before the target goes away. One looper per team does the work, the way BGameController watches controllers.

int32 "change"Other fieldsWhen
B_POWER_BATTERY_CHANGED—A battery's charge, state or time left changed, or a battery came or went. Read GetBatteryInfo() again.
B_POWER_AC_CHANGEDbool "on ac"Plugged in or unplugged.
B_POWER_PROFILE_CHANGEDint32 "profile"The power service set another profile.
B_POWER_SETTINGS_CHANGED—Someone changed the machine's power settings.
B_POWER_WILL_SLEEP, B_POWER_DID_WAKE—Reserved for sleep. Not sent yet.

Example

A view that shows the charge and the profile, and follows both.

#include <PowerRoster.h>
#include <StringView.h>

class PowerLine : public BStringView {
public:
	PowerLine() : BStringView("power", "") {}

	void AttachedToWindow()
	{
		BStringView::AttachedToWindow();
		BPowerRoster::StartWatching(BMessenger(this));
		_Update();
	}

	void DetachedFromWindow()
	{
		BPowerRoster::StopWatching(BMessenger(this));
		BStringView::DetachedFromWindow();
	}

	void MessageReceived(BMessage* message)
	{
		if (message->what == kMsgPowerChanged) {
			_Update();
			return;
		}
		BStringView::MessageReceived(message);
	}

private:
	void _Update()
	{
		BPowerRoster roster;
		BString text;
		power_battery_info info;
		if (roster.CountBatteries() > 0
			&& roster.GetBatteryInfo(0, &info) == B_OK)
			text << info.percent << " %, ";
		text << (roster.IsOnAC() ? "plugged in" : "on battery");
		if (roster.Profile() == B_POWER_PROFILE_SAVER)
			text << ", power saver";
		SetText(text.String());
	}
};

Link be libr5power.so.

Brightness

Brightness is Haiku's own call, BScreen::SetBrightness() and GetBrightness(), from 0 to 1. It reaches the graphics driver (the accelerant's B_SET_BRIGHTNESS hook, in radeon_hd and intel_extreme). Where the driver has none, the call fails: hide the control then, as the Power page does. Anyone may change the brightness; it is not a machine setting.

Without a battery, in Safe mode, before sleep

  • No battery. CountBatteries() is 0, IsOnAC() is true, and no battery message comes. The profile and the watch messages work as usual.
  • Safe mode. The power service does not run: the profile stays as the kernel started it, GetSettings() and SetSettings() return B_NO_INIT, and no profile or settings message comes. The batteries are read in the program itself, so the battery messages still come.
  • Before sleep works. CanSleep() is false and "will sleep" and "did wake" are not sent. A program that wants to prepare for sleep can watch for them already.

Where people see it

Settings, System, Power: Battery and Sleep on the left, Performance and Wake on the right. The profile for battery and for plugged in, "Turn off the display after", the lid and the power button need the administrator lock; the battery and the brightness do not. Sleep and Wake stay gray until sleep works. PowerStatus and its Deskbar item read the battery through this library. CPU Info shows the profile and how the processor's speed is set.

Limits. Dimming on battery, the low-battery notification and the thermal shutdown come with the next step. "Keep working with an external display" can only tell that a second screen is there, not which one is the built-in panel.
