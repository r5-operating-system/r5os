A page in a window

Header: /boot/system/develop/headers/r5/BServoView.h (MIT)
Library: libr5servo.so, package r5servo
Derived from: public BView

#include <r5/BServoView.h>

BWebSession* session = new BWebSession(false);
BServoView* page = new BServoView("page", session);
page->SetListener(BMessenger(this));   // load, title and address messages
window->AddChild(page);
page->LoadURL("https://www.haiku-os.org/");

A load before the view is in a window, or from another thread, waits until the view can start Servo on its window’s thread. Link with -lr5servo.

One engine per program

Servo allows one instance per process, and it stays on the thread that first starts a view. Keep every BServoView of a program in one window. A program with several windows runs Servo on a thread of its own, as Aomi does (distro/apps/aomi/ServoContentView.cpp).

Each BServoView has a drawing context of its own, and Servo starts one renderer per context, which compiles its shaders on first use; without a GPU that takes long. A program with tabs that uses the C calls directly makes the further tabs of a window with r5_servo_create_sharing(), keeps one of them visible, and so compiles once per window.

Cookies and logins are kept on disk only when the environment variable AOMI_PROFILE_DIR names a folder before the first view starts. Servo writes them when it shuts down: when the program is done with every view, it calls r5_servo_shutdown() from r5_servo_abi.h on the views’ window thread (for example in the window’s QuitRequested(), after removing the views). No new view can be made in that process afterwards. Without AOMI_PROFILE_DIR, everything stays in memory.

Input and drawing

The view takes the mouse, the wheel and the keyboard, and the Edit shortcuts (B_COPY, B_CUT, B_PASTE, B_SELECT_ALL) with the R5 clipboard. It draws the page at its own size, never stretched. A hidden view tells Servo, which then stops the page’s animation frames. Servo draws with Zink on the GPU when R5’s GPU settings allow it, and with Zink on Lavapipe otherwise.

Page questions

The view answers what a page asks: alert(), confirm(), prompt(), a sign-in (HTTP authentication), a file upload, the context menu and select lists. A program that wants its own windows, or translated words, calls r5_servo_ask_control() and r5_servo_control_answer() from r5_servo_abi.h, as Aomi does.

Messages

The listener gets the same messages as Aomi’s BWebContentView: load started, committed and finished, title, address, favicon, progress, security and protocol.

Not yet

  • A page’s request for a new window (target=_blank, window.open()) is refused and reported as AOMI_NEW_WINDOW. Aomi adopts such a window as a tab with r5_servo_set_callback().
  • Camera, location and notification permissions are denied.
  • Printing and view source return B_NOT_SUPPORTED.
