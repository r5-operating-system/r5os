Translations

Text that a user sees in an R5 program goes through Haiku's Locale Kit. The English stays in the code; each language is a file in the repository that translators edit in Weblate. A text that has not been translated, or not been checked, stays English.

In the code

Each source file names a context after its includes. The context tells a translator where the text is, so use the window or page, for example "Settings: Display". Then wrap every text a user sees.

#include <Catalog.h>
#include <StringFormat.h>

#undef B_TRANSLATION_CONTEXT
#define B_TRANSLATION_CONTEXT "Settings: Display"

BButton* apply = new BButton("apply", B_TRANSLATE("Apply"), message);

// One sentence with a placeholder, never pieces glued together.
BString text(B_TRANSLATE("The Deskbar is on screen %number%."));
text.ReplaceFirst("%number%", number);

// A count: an ICU plural, so every language picks its own form.
BString count;
BStringFormat(B_TRANSLATE("{0, plural, one{# workspace} other{# workspaces}}"))
	.Format(count, workspaces);
  • B_TRANSLATE_COMMENT(text, comment) adds a note for translators. Use it when the text alone is not clear, or must stay short.
  • In a static table, mark the text with B_TRANSLATE_MARK() and show it with B_TRANSLATE_NOCOLLECT(). Never call B_TRANSLATE in a static initializer.
  • Do not translate ids, settings keys, message fields, file paths, MIME types, view names and log lines.
  • Do not compare a shown label with English text. Compare the message or the stored value.
  • Dates and times go through BDateFormat and BTimeFormat, never a fixed strftime format.

The catalog

Add DoCatalogs to the Jamfile with the signature, without the application/ part, and the files that use B_TRANSLATE. The build extracts the English texts and installs one catalog per language in /boot/system/data/locale/catalogs/<signature>.

Application MyProgram : MyWindow.cpp : be localestub [ TargetLibstdc++ ] : MyProgram.rdef ;

DoCatalogs MyProgram :
	x-vnd.R5OS-MyProgram
	:
	MyWindow.cpp
	;

The Locale Kit finds the catalog of an image by the signature of its file. A program has one in its rdef already. An add-on or a shared library needs one of its own, or its texts stay English: give the add-on a small rdef with resource app_signature, as every Settings page does (Settings modules). When one folder builds several targets, set HAIKU_MULTIPLE_LOCALIZED_TARGETS on $(SUBDIR) = 1 ; so each gets a folder of its own.

The files

R5's own programs keep their translations in distro/catalogs/<folder>/. The folder is the program's place under objects/catalogs, for example preferences/settings/settings_display.

FileWhat it is
en.catkeysThe English, as the build extracted it. Not edited by hand.
template.potThe same texts for Weblate. Not edited by hand.
nl.po, de.po, fr.poOne file per language. Weblate edits these.

After a build that adds or changes texts, run python3 scripts/catalogs.py export haiku . and commit the result. A new program is added with --add <folder>, which also starts nl, de and fr. Before each build catalogs.py apply turns the .po files into catalogs.

Weblate

Translators work at hosted.weblate.org/projects/r5. A new folder on main becomes a component there by itself. Weblate sends its changes back as a pull request.

Only checked text ships. A first draft, made by a person or by AI, is marked "Needs editing" (the gettext fuzzy flag). The build leaves it out, so the user sees English until someone has checked the text. Where Haiku's translators already translated the same text in the same context, R5 takes their translation over.

Changing the English

Change the English in the code, build and export. The translation of the old text is kept, marked "Needs editing", with the old English next to it in Weblate, so a translator only has to check it.

Not yet

  • Not every R5 program uses B_TRANSLATE yet. Settings does; the others follow (issue #4599).
  • The languages are Dutch, German and French. Others can be added in Weblate.
