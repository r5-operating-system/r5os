Haiku kits

Additions to Haiku kits

Public calls R5 added to classes that Haiku already has. The rest of each class is as the Haiku Book describes it. A program that uses one of these calls runs on R5, not on Haiku.

What is in this page

  • BFormattingConventions::CoerceFormatForClock() — 12/24-hour pattern coercion.
  • BLocaleRoster::ApplySettings() — Applying locale changes at once.
  • BUSBEndpoint — Isochronous USB stream transfers.
  • Decorator hooks — R5 decorator ABI version and window hooks.
  • input_wheel_phase — Touchpad scroll phase on wheel messages.
  • B_USB_IOCTL_GET_DEVICE_SPEED — Querying negotiated USB speed.
  • EFI variables for drivers — Reading UEFI variables from a kernel driver.
Check before you call. These calls are not in Haiku. A program that should also run on Haiku keeps its own fallback, or builds this part only for R5.

BFormattingConventions::CoerceFormatForClock()

Locale Kit
Declared in<FormattingConventions.h>
Librarylibbe.so
Haiku BookBFormattingConventions
void CoerceFormatForClock(BString& outFormat) const;

Rewrites a time pattern so it follows the user's 12- or 24-hour choice. With the 24-hour clock it also rewrites a 12-hour pattern that has no AM/PM marker. With the 12-hour clock it adds AM/PM only when the pattern has none.

Use it when you build or store your own ICU time pattern. A pattern you store yourself is not adjusted later, so a clock that saved an English pattern kept showing 12 hours after the user chose 24. Haiku's GetTimeFormat() already applies the choice; this call does the same for your own pattern.

BFormattingConventions conventions;
BLocale::Default()->GetFormattingConventions(&conventions);

BString pattern("h:mm");
conventions.CoerceFormatForClock(pattern);	// a 24-hour pattern when the user chose 24 hours

BLocaleRoster::ApplySettings()

Locale Kit
Declared in<LocaleRoster.h>
Librarylibbe.so
Haiku BookBLocaleRoster
status_t ApplySettings(const BMessage* message);

Applies one B_LOCALE_CHANGED message on top of the settings file. A field that is not in the message keeps its value.

Haiku's Refresh() rereads the settings file. On R5 the Locale preferences broadcast a change even when the file could not be written, for example when another account owns it. A running program that only calls Refresh() would then keep the old language, country or clock. Call ApplySettings() after Refresh(), so the message wins over a stale file. Deskbar, Tracker and the audio mixer do this.

void
MyApp::MessageReceived(BMessage* message)
{
	if (message->what == B_LOCALE_CHANGED) {
		BLocaleRoster::Default()->Refresh();
		BLocaleRoster::Default()->ApplySettings(message);
		// redraw anything that shows a date, a time or a number
		return;
	}
	BApplication::MessageReceived(message);
}

BUSBEndpoint isochronous stream

Device Kit
Declared in<USBKit.h>
Librarylibdevice.so
Haiku BookBUSBEndpoint
First userThe USB webcam add-on (UVC)

Haiku's IsochronousTransfer() reads one transfer per call. What the device sends between two calls is lost, so a camera or a microphone drops data. A stream keeps transfers queued in the system and holds what arrived until you read it. There is one stream per device.

status_t StartIsochronousStream(size_t packetSize, uint32 packetsPerTransfer = 32, uint32 transferCount = 4, size_t bufferSize = 0) const;

Starts the stream on an isochronous input endpoint: transferCount transfers of packetsPerTransfer packets stay queued, and up to bufferSize bytes are held. B_BAD_VALUE for an endpoint or interface that does not fit, B_NO_MEMORY when the buffers cannot be made.

ssize_t ReadIsochronousStream(void* data, size_t length, bigtime_t timeout) const;

Waits up to timeout for packets and stores them one after another, each as a usb_stream_packet_header followed by its data. A packet without data is left out. Returns the number of bytes stored, B_TIMED_OUT, or another error when the stream has ended.

status_t StopIsochronousStream() const;

Stops the stream, so another one can be started.

struct usb_stream_packet_header { uint16 length; uint16 flags; };

length is the size of the data that follows. B_USB_STREAM_PACKET_ERROR: the packet arrived with an error. B_USB_STREAM_PACKET_GAP: packets before this one were lost.

if (endpoint->StartIsochronousStream(packetSize) != B_OK)
	return;

while (running) {
	ssize_t length = endpoint->ReadIsochronousStream(buffer, size, 100000);
	if (length == B_TIMED_OUT)
		continue;
	if (length < 0)
		break;		// the stream has ended

	size_t offset = 0;
	while (offset + sizeof(usb_stream_packet_header) <= (size_t)length) {
		usb_stream_packet_header header;
		memcpy(&header, buffer + offset, sizeof(header));
		offset += sizeof(header);
		if (offset + header.length > (size_t)length)
			break;
		handle_packet(buffer + offset, header.length, header.flags);
		offset += header.length;
	}
}
endpoint->StopIsochronousStream();

Decorator hooks and the decorator ABI version

Decorators (app_server add-ons)
Declared insrc/servers/app/decorator/Decorator.h (private to app_server)
Installed in/system/add-ons/decorators
ForDecorator add-ons, not applications
First userThe R5 decorator (R5 2026.1, M11 step 1)

A decorator draws the window frame: the tab, the buttons and the border. It is an add-on that subclasses Haiku's Decorator and exports instantiate_decor_addon(), as on Haiku. Applications do not see any of this; they keep talking to app_server through BWindow.

R5 adds three hooks at the end of Decorator. Each has a default, so a decorator only overrides the ones it needs. The rectangles hold a width per side, not a position.

virtual void GetShadowExtent(BRect* extent);

How far the window shadow reaches past the border on each side. The default is a small shadow that falls down, derived from the border width. The shadow is drawn only when windows are composed on the GPU; until then the value is unused.

virtual void GetGlassRegion(BRegion* region);

The part of the frame, in screen coordinates, that is frosted glass when windows are composed on the GPU. The default is empty: no glass.

virtual void GetInputMargin(BRect* margin);

An area outside the border where the window can be resized, although nothing is drawn there. It is not part of the footprint, does not cover the windows below, and has no pixels. The default is 0 on every side. Return 0 for a side that cannot be resized (B_NOT_RESIZABLE, B_NOT_H_RESIZABLE, B_NOT_V_RESIZABLE), and classify the margin in RegionAt() as a border or a corner.

virtual int32 GetOutline(window_outline_rect* rects, int32 maxCount);

ABI 2. The window's outline with round corners: up to maxCount rectangles in screen coordinates, the frame first and then the tabs, each with the radius of its four corners in pixels (leftTop, rightTop, leftBottom, rightBottom; 0 is square). Return how many you wrote. The default returns 0: the window keeps its square footprint, pixel for pixel. The corners outside the arc stop being part of the window, in the CPU mode as a stepped arc and on the GPU anti-aliased, and the content is clipped there too. Where another rectangle (a tab) lies behind a cut corner of the frame, the pixels stay the window's: the tab card of Default (R5 Modern) reaches 14 px under the window, so its colour shows in the window's round top corners, and the decorator draws those pixels itself (they are part of its footprint).

virtual bool GetEdgeLine(rgb_color* color, float* width);

ABI 2. The colour and width of the line your decorator draws along the outer edge of the window. When the window has round corners, app_server carries that line round the arc in the same colour, so it does not stop where the corner begins. Return false (the default) when your decorator draws no such line. The line runs round the corners of the frame, the first rectangle of GetOutline(), not round a tab's: a tab that wants an edge draws it. On the GPU the colour's alpha counts: white at alpha 191 is a light line over the window's own pixels.

bool InputMarginContains(BPoint where);

Not a hook: whether where lies in the input margin, outside the border, or, with an outline, in a cut corner of the frame (outside the arc). app_server uses it to find the window under the mouse, so the round corner of a window that can be resized is its resize corner and not the window behind. Return that corner from RegionAt(). The cut top corners of a tab still let a click through to what lies behind.

The ABI version

The hooks change the layout of Decorator, so an add-on built before them would crash app_server. Every decorator add-on therefore exports the ABI version it was built with. Put R5_DECORATOR_ABI_EXPORT in one source file of the add-on. app_server loads only an add-on with the current version (R5_DECORATOR_ABI_VERSION, now 2). Any other add-on is refused with one line in the syslog, and the default decorator is used:

app_server: decorator OldDecorator refused: abi 1, need 2

Rebuild an old decorator against the R5 headers to fix that. A new hook comes after the last one, and the version goes up by one: version 2 added GetOutline() and GetEdgeLine().

The default decorator

On R5 the R5 decorator is the default. app_server loads it when no decorator was chosen, and BPrivate::DecorInfoUtility::DefaultDecorator() returns it when it is installed, so Defaults in Appearance picks it. "Default" still names Haiku's built-in decorator; a program that sets it gets Haiku's look. When the R5 decorator is missing, both fall back to the built-in one.

The decorators of R5 and their names

Appearance (Look and feel, in Settings and in the separate Appearance program) lists the decorators by the name in their be:decor:info resource, the add-ons sorted by name and Haiku's built-in decorator last:

Default (R5 Modern)R5ModernDecorator: round corners (18 px), a soft tab card behind the window, Haiku's buttons with a glass finish.
Default (R5)R5Decorator, the default: Haiku's tab and buttons with a 1 px frame.
Classic (Haiku)The built-in decorator ("Default"), exactly as in Haiku.

Give your add-on a name the same way ("name" in the resource); without one the file name is shown. DecorInfoUtility::FindDecorator() finds a decorator by its path, its name or its file name.

Resizing by the edge

On R5, dragging a border or a corner with the primary button resizes the window on that side, with every decorator, and the resize cursor shows while the mouse is over it. Dragging the tab moves the window. A window that cannot be resized in that direction is moved, as on Haiku.

#include "DecorManager.h"
#include "SATDecorator.h"

class MyDecorator : public SATDecorator {
public:
	MyDecorator(DesktopSettings& settings, BRect frame, Desktop* desktop)
		: SATDecorator(settings, frame, desktop) {}

	virtual void GetGlassRegion(BRegion* region)
	{
		region->MakeEmpty();
		region->Include(&fTabsRegion);	// the tab is glass
	}
};

class MyDecorAddOn : public DecorAddOn {
public:
	MyDecorAddOn(image_id id, const char* name) : DecorAddOn(id, name) {}

protected:
	virtual Decorator* _AllocateDecorator(DesktopSettings& settings,
		BRect rect, Desktop* desktop)
	{
		return new (std::nothrow) MyDecorator(settings, rect, desktop);
	}
};

R5_DECORATOR_ABI_EXPORT	// without it, app_server refuses the add-on

extern "C" DecorAddOn*
instantiate_decor_addon(image_id id, const char* name)
{
	return new (std::nothrow) MyDecorAddOn(id, name);
}

input_wheel_phase

Interface Kit (input)
Declared in<Input.h>
Sent bythe mouse add-on of input_server, for a touchpad
Haiku BookB_MOUSE_WHEEL_CHANGED

Haiku's be:wheel_delta_x and be:wheel_delta_y are whole wheel steps, and say nothing about when a gesture starts or stops. When two fingers scroll on a touchpad, R5 adds three fields to B_MOUSE_WHEEL_CHANGED. The whole-step fields stay as they are, so a Haiku program keeps working.

FieldTypeMeaning
be:wheel_precise_delta_x, be:wheel_precise_delta_yfloatThe same movement in wheel steps, with fractions, for smooth scrolling.
be:wheel_phaseint32An input_wheel_phase.
enum input_wheel_phase { B_WHEEL_PHASE_NONE = 0, B_WHEEL_PHASE_BEGAN = 1, B_WHEEL_PHASE_CHANGED = 2, B_WHEEL_PHASE_ENDED = 3 };

BEGAN when the fingers start scrolling, CHANGED while they move, ENDED when they lift or start moving the pointer. The ended message can have no movement at all; it only says the gesture is over. A mouse wheel sends no phase.

case B_MOUSE_WHEEL_CHANGED:
{
	int32 phase;
	float dy;
	if (message->FindInt32("be:wheel_phase", &phase) == B_OK
		&& message->FindFloat("be:wheel_precise_delta_y", &dy) == B_OK) {
		ScrollSmoothly(dy);
		if (phase == B_WHEEL_PHASE_ENDED)
			SettleScroll();		// for example, snap to a line
		break;
	}
	BView::MessageReceived(message);	// a mouse wheel: whole steps
	break;
}

B_USB_IOCTL_GET_DEVICE_SPEED

USB (drivers)
Declared in<usb/R5USBSpeed.h>
Modulebus_managers/usb (USB module v3)
ForKernel drivers

Haiku's USB module does not tell a driver at which speed its device runs. R5 answers that through the existing usb_ioctl() of the module; the module structure is unchanged. The value is one of B_USB_SPEED_LOW, _FULL, _HIGH, _SUPER and _SUPER_PLUS. A USB audio driver needs it to size its packets: a high-speed device takes eight packets per millisecond, a full-speed device one.

status_t usb_ioctl(B_USB_IOCTL_GET_DEVICE_SPEED, uint32* value, sizeof(uint32));

In: the usb_device in *value. Out: its speed. B_BAD_VALUE when the ID is not a device. On Haiku, and on R5 before build 10058, the call returns B_DEV_INVALID_IOCTL; keep a fallback.

uint32 speed = (uint32)device;
bool highSpeed;
if (gUSBModule->usb_ioctl(B_USB_IOCTL_GET_DEVICE_SPEED, &speed,
		sizeof(speed)) == B_OK)
	highSpeed = speed >= B_USB_SPEED_HIGH;
else
	highSpeed = guess_from_descriptors();	// your own fallback

EFI variables for drivers

EFI (drivers)
Declared in<EFI.h>
Modulegeneric/efi/v1 (B_EFI_MODULE_NAME)
ForKernel drivers

On a machine that starts through UEFI, a kernel driver can read firmware variables, for example factory calibration that the vendor stores in EFI. The module is a normal kernel module, used like the ACPI module: get_module(), the calls, put_module(). The firmware runs in an address space of its own and never sees the caller's memory.

The module may be absent. get_module() fails on a legacy BIOS start, in safe mode, on an architecture without a backend (today only x86_64 has one), and when the firmware's runtime map is unusable. A driver must work without it.
status_t get_variable(const char* name, const efi_vendor_guid* vendor, void* buffer, size_t* _size, uint32* _attributes);

Reads the variable name (UTF-8) of vendor. *_size is the size of buffer on entry and the size of the variable on return. B_BUFFER_OVERFLOW when the buffer is too small (the size is still set); pass NULL and *_size 0 to ask for the size. B_ENTRY_NOT_FOUND when the variable does not exist. _attributes may be NULL; otherwise it gets B_EFI_VARIABLE_NON_VOLATILE, _BOOTSERVICE_ACCESS and _RUNTIME_ACCESS as the firmware reports them.

status_t get_next_variable_name(char* name, size_t nameSize, efi_vendor_guid* vendor);

Steps through all variable names. Start with an empty name; each call returns the next name and its vendor GUID. B_ENTRY_NOT_FOUND after the last one.

When you may call

Only from a thread, never from an interrupt handler, with interrupts off, or with a spinlock held. A call can wait for another caller and then runs the firmware with interrupts off for that one call; a read takes well under a millisecond on the machines tested, but flash-backed firmware can take longer. A call with interrupts off is refused with B_NOT_ALLOWED. If the firmware faults, the call fails and the module stops calling the firmware until the next start.

static const efi_vendor_guid kGlobalVariable = { 0x8be4df61, 0x93ca, 0x11d2,
	{ 0xaa, 0x0d, 0x00, 0xe0, 0x98, 0x03, 0x2b, 0x8c } };

efi_module_info* efi;
if (get_module(B_EFI_MODULE_NAME, (module_info**)&efi) == B_OK) {
	uint16 order[32];
	size_t size = sizeof(order);
	if (efi->get_variable("BootOrder", &kGlobalVariable, order, &size,
			NULL) == B_OK)
		dprintf("%u boot entries\n", (unsigned)(size / 2));
	put_module(B_EFI_MODULE_NAME);
} else {
	// no EFI runtime services: use your own defaults
}

Writing variables (SetVariable) is not available yet. Calls are only ever added at the end of efi_module_info, so a driver built against this version keeps working.
