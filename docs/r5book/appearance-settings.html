BAdminLockBar

class
Declared in<AdminLock.h>
Librarylibr5ui.so
Derived fromBGroupView
First userTime, Screen, Network, Printers, Repositories, VirtualMemory, Users, Settings; Device Manager; Media (the calls, not the bar)

BAdminLockBar is the lock for machine settings. A program runs as the signed-in person; a change that needs an administrator goes to Sign in (Login), which checks the grant and makes the change.

The bar shows a label and an Unlock button. While locked, views in its window are gray; an administrator starts unlocked, and one unlock opens the program for five minutes. AdminLockBar is a typedef for this class, the name the preferences have always used.

It was compiled into each preference under GPL-3.0-or-later. Since November 2026 it is part of libr5ui.so and MIT, so any program can link it. Login, the side that checks the password, stays GPL and is reached only by messages.

Use it for

A window that changes the whole computer: the clock, the screen mode, network, printers, drivers.

Not for

The person's own settings. Those need no administrator and stay unlocked.

BAdminLockBar();

Put it in the window's bottom row. It asks Login when it is attached and watches the grant.

void SetExempt(BView* view, bool exempt);

Keeps one view usable while the lock is closed, for example the person's own account card in Users.

bool AcceptsInput(BHandler* target) const;

Whether a click or key for target goes through now.

status_t r5_admin_query(bool& administrator, bool& unlocked); bool r5_admin_change_allowed();

Asks Login. unlocked is true for an administrator or while a grant runs. Both are false when Login cannot be asked.

void r5_admin_prompt_unlock(BMessenger target); status_t r5_admin_unlock(const char* name, const char* password, BString& error); status_t r5_admin_relock();

The unlock window, the same without a window, and ending the grant. On success the window sends kMsgAdminLockChanged to target. The password is not logged.

status_t r5_admin_set_clock(unsigned long seconds); status_t r5_admin_set_timezone(int32 offset, const char* name); status_t r5_admin_set_clock_gmt(bool gmt);

The clock and the time zone, for Time and Settings.

status_t r5_admin_set_driver_blocked(const char* driver, bool blocked, BString& error);

Turns a packaged driver under /boot/system/add-ons/kernel/ off or on for the next start. Login refuses drivers the system needs to start. Device Manager uses it.

bool r5_driver_settings_writable(); status_t r5_driver_settings_read(const char* fileName, const char* key, BString& value); status_t r5_driver_settings_write(const char* fileName, const char* const* keys, int32 keyCount, const char* lines, bool replaceFile);

Driver settings: the files a driver reads with load_driver_settings(). The kernel reads them from the administrator's config/settings/kernel/drivers, not from the signed-in person's home, so these calls always use that folder. writable says whether this program may write there itself. read gives the text after key on its line, or B_NAME_NOT_FOUND. write replaces the lines that start with one of keys by lines and keeps the rest; with replaceFile the file is only lines. It writes a temporary file and renames it, so a crash never leaves an empty file. fileName is a name in that folder, without a slash.

status_t r5_admin_set_driver_setting(const char* fileName, const char* const* keys, int32 keyCount, const char* lines, bool replaceFile, BString& error);

The same write through Login, for a standard account with a grant. Login accepts only the settings it knows, today those of Media: the buffer size (play_buffer_frames, record_buffer_frames) in hda.settings and usb_audio, the USB channel layout, and virtual surround. Anything else is refused.

static const char* kKeys[] = { "channel_layout" };
BString error;
status_t status;
if (r5_driver_settings_writable()) {
	status = r5_driver_settings_write("usb_audio", kKeys, 1,
		"channel_layout 6\n", false);
} else {
	// Gray until r5_admin_change_allowed(); then Login writes it.
	status = r5_admin_set_driver_setting("usb_audio", kKeys, 1,
		"channel_layout 6\n", false, error);
}

BPageHeader

class
Declared in<PageHeader.h>
Librarylibr5ui.so
Derived fromBCard
First userSettings; Users & Accounts is the second

BPageHeader is the heading card at the top of a page: a small category line (the eyebrow), the title, a description, and an icon on the right. It draws itself and has no child views.

BPageHeader(const char* name);
void SetEyebrow(const char* text); void SetTitle(const char* text); void SetSubtitle(const char* text); void SetIcon(const BBitmap* icon);

An empty eyebrow hides that line without leaving a gap. The title is bold, 8 points above the bold font; the subtitle is plain at 70 percent text color. Each line ends with an ellipsis when it does not fit. The icon is ComposeIconSize(40); draw any wrench on it before SetIcon(), which keeps a copy.

BAppearanceKit::BPageHeader* heading = new BAppearanceKit::BPageHeader("heading");
heading->SetEyebrow("System");
heading->SetTitle("Notifications");
heading->SetSubtitle("Manage alerts and notifications");
heading->SetIcon(icon);
See also BCard Settings modules

BSidebar

class
Declared in<Sidebar.h>
Librarylibr5ui.so
Derived fromBOutlineListView
First userSettings, beside the page

BSidebar is a list of categories that fold, with one category open at a time, and a filter for search. The rows are BSidebarItems: categories at the top level, pages under them with AddUnder(). Wrap it in a BScrollView.

BSidebar(const char* name);
void SetSingleExpand(bool single); bool IsSingleExpand() const; void ExpandOnly(BSidebarItem* section);

One category unfolds at a time by default. ExpandOnly(NULL) folds them all.

BSidebarItem* ItemForId(const char* id) const; bool SelectId(const char* id);

SelectId() unfolds the parent, selects the row and scrolls it into view. It returns false when the id is missing.

void SetFilter(const char* text); const char* Filter() const;

Hides pages whose label and keywords do not contain the text, ignoring case, and unfolds every category that still has a match. An empty filter puts every row back. Rows are hidden, not deleted.

void SetFooter(const char* text);

A panel at the bottom of the list.

Up and Down move and skip a separator, Right unfolds, Left folds, Enter posts the selection message.

BAppearanceKit::BSidebar* list = new BAppearanceKit::BSidebar("sidebar");
list->AddItem(home);
list->AddItem(system);
list->AddUnder(display, system);
list->SetFilter("display");
See also BSidebarItem BCardStrip

BSidebarItem

class
Declared in<SidebarItem.h>
Librarylibr5ui.so
Derived fromBListItem

One row of a BSidebar: Home, a category, or a page. An empty label and an empty id make a separator, which cannot be selected.

Only a top-level row draws its icon; a page's text starts where the category name starts. The selection is a rounded rectangle in the selection blue with the text in the list background color.

BSidebarItem(const char* label, const char* id, const BBitmap* icon = NULL);
void SetCount(int32 count);

Drawn on the right of a folded category.

void SetBadge(sidebar_badge badge);

B_SIDEBAR_BADGE_LOCKED draws the small closed lock on a page that needs an administrator.

void SetEmphasized(bool bold);

A bold row, such as Home. It stays visible while a filter is active.

void SetKeywords(const char* keywords);

Extra words the filter matches, beyond the label.

void SetIcon(const BBitmap* icon); const char* Label() const; const char* Id() const;
BAppearanceKit::BSidebarItem* home = new BAppearanceKit::BSidebarItem(
	"Home", "home", pebble);
home->SetEmphasized(true);
See also BSidebar

BUserCard

class
Declared in<UserCard.h>
Librarylibr5ui.so
Derived fromBControl
First userSign in, for two to four accounts

BUserCard is a compact account card showing the account picture, display name, and role. It sends its message when clicked, or with Space or Enter.

The selected card has a blue border. An administrator's role is bold and blue, and the picture of anyone else is gray.

BUserCard(const char* name, const char* login, const char* displayName, const char* role, const BBitmap* avatar = NULL, BMessage* message = NULL);

Render the avatar at r5_avatar_icon_side() of the card's picture size so it is drawn pixel for pixel.

void SetSelected(bool selected); bool IsSelected() const;
void SetDisplayName(const char* displayName); void SetRole(const char* role); void SetAvatar(const BBitmap* avatar);

BUserListItem

class
Declared in<UserListItem.h>
Librarylibr5ui.so
Derived fromBListItem
First userSign in, for five accounts or more

BUserListItem is a two-line account row for a BListView: the picture, the name in bold, and @login · role below it.

Only the role is blue, and only for an administrator. The selected row is light blue with a bar on the left.

BUserListItem(const char* login, const char* displayName, const char* role, const BBitmap* avatar = NULL);

The row is 46 pixels high at a 12 point font.

const char* Login() const; const char* DisplayName() const; const char* Role() const;
