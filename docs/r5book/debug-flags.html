Debug flags

The switches R5 reads from settings files and environment variables: extra logging, tests, tuning, and the few normal on/off settings that live next to them. They are for developers and test sticks. A normal installation needs none of them.

What is in this page

  • How the settings files work — where they live, defaults, the release default.
  • radeon_hd — GPU, compositor, Skia drawing, Lavapipe.
  • kernel — memory, power, cache and boot reports, the syslog.
  • efi and safe mode — EFI runtime services.
  • Audio — speaker amplifiers, USB audio, HD Audio, the mixer.
  • Wi-Fi, Bluetooth and the network — mt7922wifi, h2generic, WiFi_debug, discovery.
  • Environment variables — Lavapipe, Mesa, tests.
Test switches change behaviour. A switch marked test runs a test or forces a failure on purpose (a GPU hang, a failed submit). Use it on a test stick, not on a machine you work on.

How the settings files work

Settings files

A kernel driver reads ~/config/settings/kernel/drivers/<name> with load_driver_settings("<name>"). One switch per line, for example gpu_debug true. A change takes effect on the next start unless the table says otherwise.

TermMeaning
defaultThe value when the line is not in the file.
bareThe value when the key is there without a value. Switches with bare = false need an explicit true.
release defaultRead through the GPU switch rule: the file's value if it names one; otherwise on, but only on a release-supported GPU (today the Ryzen 5 5625U, 0x15e7) without gpu false; and always off with gpu false.
exact formapp_server, Login and the R5 DRM library read the radeon_hd file line by line and only understand the exact form shown, for example gpu_debug true. Comments and bare keys do not work there.

Kinds: debug and trace only add logging; test runs a test or forces a failure; tuning changes behaviour or speed; feature is a normal on/off setting.
